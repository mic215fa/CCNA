# Multilayer Switching Packet Flow

> [!info] Knowledge-map role
> 這份流程 Map 展開 [[12.4-Multilayer Switch]] 使用 SVI 與 routed port 的 forwarding 過程。

## Definition

[[12.4-Multilayer Switch]] 同時執行 Layer 2 switching 與 Layer 3 routing。它使用 [[Switch Virtual Interface|SVIs]] 作為各 VLAN 的 default gateways，在 switch 內部完成 inter-VLAN routing，不必讓封包繞到外接 router。

這份筆記以 Chapter 12.4.2 的兩類範例說明：

1. Figure 12.11：PC1（VLAN 10）到 PC5（VLAN 30）的內部 inter-VLAN packet flow。
2. Figures 12.12、12.13：SW1 透過 routed port 與 R1 到達 external networks。

## Why It Exists

ROAS 仍必須讓每個跨 VLAN packet 往返外接 router。Multilayer switch 將 routing function 放在 switch 內部，使 LAN 內 VLAN 間的 traffic 可在同一設備完成 Layer 2 → Layer 3 → Layer 2 forwarding。

```text
Access switching
      ↓
VLAN SVI（default gateway）
      ↓ internal routing
另一個 VLAN SVI
      ↓
Access 或 trunk forwarding
```

## Example 1：PC1（VLAN 10）到 PC5（VLAN 30）

![](../00_Source/images/0f86a34f-6bf0-4f73-9c16-fc4f38df6c5c-239_1026_1418_529_190.jpg)
*Source: [[00_Source/Chapter 12.4.2 - Multilayer switching|Chapter 12.4.2]], Figure 12.11 — SW1 routes PC1's packet internally from the VLAN 10 SVI to the VLAN 30 SVI, then sends it across the trunk to PC5.*

Figure 12.11 中，SW1 具有三個 SVIs：

| VLAN | Subnet | SVI/default gateway |
|---|---|---|
| 10 | `172.16.1.0/26` | `Vlan10` — `172.16.1.1` |
| 20 | `172.16.1.64/26` | `Vlan20` — `172.16.1.65` |
| 30 | `172.16.1.128/26` | `Vlan30` — `172.16.1.129` |

每個 SVI 有自己的 IP address 與 unique MAC address。這與 ROAS 的 subinterfaces 共用 physical router interface MAC 不同。

## Step 1：PC1 將 Packet 交給 VLAN 10 SVI

PC1 判斷 PC5 位於不同 subnet，因此 next hop 是 VLAN 10 的 default gateway `172.16.1.1`。若 ARP cache 尚無紀錄，PC1 先解析 VLAN 10 SVI 的 MAC。

PC1 建立：

```text
Ethernet frame
├─ Src MAC = PC1-MAC
├─ Dst MAC = SW1-VLAN10-SVI-MAC
└─ IP packet
   ├─ Src IP = PC1-IP
   └─ Dst IP = PC5-IP
```

PC1 從 access link 送出 untagged frame；SW1 的 `G1/0` access port 根據 port assignment 將它歸入 VLAN 10。

> [!important]
> PC1 的 destination MAC 是本地 next hop，也就是 VLAN 10 SVI；destination IP 才是最終目的 PC5。

## Step 2：SW1 將 Frame 交給 Internal Router

SW1 在 VLAN 10 的 Layer 2 forwarding context 中看到 destination MAC 屬於自己的 VLAN 10 SVI，因此不把 frame flood 到其他 ports，而是交給 internal Layer 3 routing function。

```text
Ingress G1/0 access VLAN 10
        ↓
Destination MAC = VLAN 10 SVI MAC
        ↓
Vlan10 SVI
        ↓
移除原 Ethernet encapsulation
```

## Step 3：SW1 查詢 Routing Table

啟用 `ip routing` 後，SW1 會為 up/up SVIs 建立 connected/local routes。PC5-IP 位於 `172.16.1.128/26`，因此 routing table 選擇 VLAN 30 SVI 作為 Layer 3 exit interface。

```text
Destination IP = PC5-IP
        ↓ longest-prefix match
172.16.1.128/26 is directly connected, Vlan30
        ↓
Exit Layer 3 interface = Vlan30
```

SW1 執行 routing 時 TTL 減 1。Source/destination IP 保持 PC1-IP 與 PC5-IP；原 Layer 2 frame 則不會被保留。

## Step 4：VLAN 30 SVI 建立新的 Frame

若 SW1 尚未知道 PC5-MAC，VLAN 30 SVI 先在 VLAN 30 執行 ARP。之後由 VLAN 30 SVI 建立新的 Ethernet frame：

```text
New Ethernet frame
├─ Src MAC = SW1-VLAN30-SVI-MAC
├─ Dst MAC = PC5-MAC
└─ IP packet
   ├─ Src IP = PC1-IP
   └─ Dst IP = PC5-IP
```

這一步清楚顯示 multilayer switch 內部的 Layer 3 boundary：ingress frame 的 source/destination MAC 是 PC1 → VLAN 10 SVI；egress frame 則改為 VLAN 30 SVI → PC5。

## Step 5：SW1 透過 Trunk 將 VLAN 30 Frame 送至 SW2

SW1 查詢 VLAN 30 的 MAC address table，得知 PC5 位於 SW2 方向，因此從 `G0/0` trunk 送出 frame 並加入 VLAN 30 tag。

```text
SW1 internal router / Vlan30
 │ new Layer 2 frame
 ▼
SW1 G0/0 trunk
 │ tagged，802.1Q VID = 30
 ▼
SW2 G0/0 trunk
```

## Step 6：SW2 將 Untagged Frame 交給 PC5

SW2 依 802.1Q tag 將 ingress frame 歸入 VLAN 30，再依 PC5-MAC 從 `G1/2` access port 送出。Access egress 移除 VLAN tag，PC5 收到 untagged Ethernet frame。

## Complete Internal Inter-VLAN Flow

```text
PC1 (VLAN 10)
 │ untagged; Dst MAC = VLAN 10 SVI
 ▼
SW1 G1/0 access port
 │ classify as VLAN 10
 ▼
SW1 Vlan10 SVI
 │ remove old L2 frame
 │ route by PC5 destination IP
 ▼
SW1 Vlan30 SVI
 │ new frame; Src MAC = VLAN 30 SVI
 ▼
SW1 G0/0 ===== tagged VLAN 30 trunk ===== SW2 G0/0
 │ remove tag on access egress
 ▼
SW2 G1/2
 │ untagged
 ▼
PC5 (VLAN 30)
```

## Header and Tag Changes

| Path segment | Src MAC | Dst MAC | Src IP | Dst IP | 802.1Q tag |
|---|---|---|---|---|---|
| PC1 → SW1 access port | PC1 | VLAN 10 SVI | PC1 | PC5 | None |
| Inside SW1 before routing | PC1 | VLAN 10 SVI | PC1 | PC5 | Internal VLAN 10 context |
| SW1 → SW2 trunk | VLAN 30 SVI | PC5 | PC1 | PC5 | VLAN 30 |
| SW2 access port → PC5 | VLAN 30 SVI | PC5 | PC1 | PC5 | None |

## Configuration That Makes SVI Routing Possible

```text
SW1(config)# ip routing
SW1(config)# interface vlan 10
SW1(config-if)# ip address 172.16.1.1 255.255.255.192
SW1(config)# interface vlan 20
SW1(config-if)# ip address 172.16.1.65 255.255.255.192
SW1(config)# interface vlan 30
SW1(config-if)# ip address 172.16.1.129 255.255.255.192
```

`interface vlan 30` 中的 VLAN ID 具有實際意義，直接指定 SVI 與 VLAN 30 的關聯；這點不同於 ROAS subinterface 名稱中的 `.30` identifier。

## SVI 必須 Up/Up

上述 flow 的入口 VLAN 10 SVI 與出口 VLAN 30 SVI 都必須 up/up。每個 SVI 必須同時滿足：

1. 對應 VLAN 已存在。
2. 至少有一個屬於該 VLAN 的 up/up access port，或一個允許該 VLAN 的 up/up trunk port。
3. VLAN 本身未被 `shutdown`。
4. SVI 本身未被 `shutdown`。

如果 VLAN 30 SVI down，SW1 就無法把 packet 經由該 Layer 3 interface route 進 VLAN 30，即使 PC5 的 physical access link 看似正常。

## Example 2：透過 Routed Port 到 External Networks

![](../00_Source/images/0f86a34f-6bf0-4f73-9c16-fc4f38df6c5c-242_772_1417_349_220.jpg)
*Source: [[00_Source/Chapter 12.4.2 - Multilayer switching|Chapter 12.4.2]], Figure 12.12 — SW1 G0/1 is a routed port using 172.16.1.193/30; R1 G0/0 uses 172.16.1.194/30.*

Figure 12.12 中，SW1 `G0/1` 使用 `no switchport` 從 Layer 2 switchport 轉為 routed port：

```text
SW1(config)# interface g0/1
SW1(config-if)# no switchport
SW1(config-if)# ip address 172.16.1.193 255.255.255.252
SW1(config)# ip route 0.0.0.0 0.0.0.0 172.16.1.194
```

`G0/1` 不再屬於某個 VLAN，也不使用 `switchport access` 或 `switchport trunk` 行為；它像 router physical interface 一樣擁有 IP address，並讓 SW1 routing table 出現 connected/local routes。

![](../00_Source/images/0f86a34f-6bf0-4f73-9c16-fc4f38df6c5c-243_987_1241_1023_316.jpg)
*Source: [[00_Source/Chapter 12.4.2 - Multilayer switching|Chapter 12.4.2]], Figure 12.13 — A VLAN 10 host sends traffic through its SVI; SW1's internal router follows the default route and forwards the packet through routed port G0/1 to R1 and external networks.*

以 Figure 12.13 的 VLAN 10 host 傳送 packet 到 external destination 為例：

1. Host 判斷 destination 不在本地 subnet，將 frame 送到 VLAN 10 SVI MAC。
2. SW1 在 VLAN 10 SVI 移除 ingress Layer 2 frame，查詢 destination IP。
3. 沒有更具體 route 時，SW1 使用 default route `0.0.0.0/0 via 172.16.1.194`。
4. SW1 從 routed port `G0/1` 建立新的 Ethernet frame：source MAC 是 SW1 G0/1，destination MAC 是 next-hop R1 G0/0。
5. R1 收到 packet 後繼續根據 destination IP route 至 external network。

```text
VLAN 10 host
 │ Dst MAC = VLAN 10 SVI
 ▼
SW1 Vlan10 SVI
 │ internal routing
 │ default route via 172.16.1.194
 ▼
SW1 G0/1 routed port 172.16.1.193/30
 │ Dst MAC = R1 G0/0
 ▼
R1 G0/0 172.16.1.194/30
 │ routing
 ▼
External networks
```

## SVI、Trunk 與 Routed Port 的分工

| Component | Layer | Role in the examples |
|---|---|---|
| Access port | Layer 2 | 將 untagged host traffic 歸入單一 VLAN |
| Trunk port | Layer 2 | 在 SW1 與 SW2 間以 802.1Q tag 攜帶多個 VLAN |
| SVI | Layer 3 | 作為 VLAN default gateway，讓 internal router 進出該 VLAN |
| Routed port | Layer 3 | 直接連接另一個 Layer 3 device/subnet，不屬於任何 VLAN |
| Routing table | Layer 3 | 決定 packet 前往另一個 SVI、routed port 或 next hop |

## Contrast With ROAS

| Aspect | [[04_Maps/12.4-Router-on-a-Stick-Packet-Flow|ROAS]] | Multilayer switching |
|---|---|---|
| Default gateways | Router subinterfaces | Switch SVIs |
| VLAN間 routing location | External router | Inside multilayer switch |
| Link carrying VLANs to routing function | Physical trunk to router | Internal switch path |
| Interface MAC behavior | Subinterfaces share physical interface MAC | Each SVI has a unique MAC |
| External connectivity | Router 本身可繼續 route | 常以 routed port 連到上游 router |

## Common Confusions

- VLAN 是 Layer 2 broadcast domain；SVI 是與 VLAN 關聯的 Layer 3 interface，兩者不是同一物件。
- `interface vlan 30` 建立的是 SVI，不是建立 VLAN 30 本身；VLAN 必須存在且具備 active member link，SVI 才能 up/up。
- `no switchport` 會把 physical port 變成 Layer 3 routed port；它不再是 access 或 trunk port。
- Figure 12.11 的 packet 確實經過 routing；只是 Layer 3 routing 發生在 SW1 內部，而不是外接 R1。
- Trunk tag 只描述目前 Layer 2 frame 所屬 VLAN，不會取代 destination IP 或 routing table lookup。

## Questions

- 為什麼 Figure 12.11 的 ingress frame 目的 MAC 是 VLAN 10 SVI，而 egress frame 的 source MAC 是 VLAN 30 SVI？
- 若 SW1 忘記設定 `ip routing`，三個 SVIs 即使 up/up，為什麼仍不能完成 inter-VLAN routing？
- 若 SW1–SW2 trunk 不允許 VLAN 30，packet flow 會在哪一步中斷？
- SVI 已設定 IP address，但其 VLAN 沒有任何 active access/trunk member 時，為什麼 SVI 不能 forwarding？
- Figure 12.13 中為什麼需要 default route，而 Figure 12.11 的三個本地 VLAN 不需要 static routes？
