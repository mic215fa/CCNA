# Router on a Stick Packet Flow

## Definition

Router on a Stick（ROAS）讓一個 router physical interface 透過多個 [[Subinterface|subinterfaces]] 與一條 [[Trunk Port|802.1Q trunk]]，替多個 VLAN 執行 [[Inter-VLAN Routing]]。

這份筆記使用 Chapter 12.4.1 的 Figure 12.10，追蹤 PC3（VLAN 20）傳送 packet 到 PC10（VLAN 10）的完整過程。

## Why It Exists

傳統 inter-VLAN routing 需要每個 VLAN 各占用一個 router physical interface。ROAS 將單一 physical interface 虛擬化成多個 subinterfaces，避免 VLAN 數量受 router ports 數量直接限制。

```text
一個 VLAN 一條 physical link
          ↓ physical ports 很快用完
一條 trunk + 多個 subinterfaces
          ↓
多個 VLAN 共用同一 router physical interface
```

*Source: [[00_Source/Chapter 12.4.1 - Router on a stick|Chapter 12.4.1]], Figure 12.10 — PC3 in VLAN 20 sends a packet to PC10 in VLAN 10 through R1's ROAS subinterfaces.*

Figure 12.10 使用以下 VLAN 與 gateway 對應：

| VLAN | Subnet | R1 subinterface | Default gateway |
|---|---|---|---|
| 10 | `172.16.1.0/26` | `G0/0.10` | `172.16.1.1` |
| 20 | `172.16.1.64/26` | `G0/0.20` | `172.16.1.65` |
| 30 | `172.16.1.128/26` | `G0/0.30` | `172.16.1.129` |

Router 的 `G0/0` 與三個 subinterfaces 共用同一個 MAC address。Router 不是依 destination MAC 區分 subinterface，而是依收到 frame 的 [[VLAN ID|802.1Q VLAN ID]] 將 frame 交給對應 subinterface。

## Step 1：PC3 判斷 PC10 位於不同 Subnet

PC3 屬於 VLAN 20 的 `172.16.1.64/26`，PC10 屬於 VLAN 10 的 `172.16.1.0/26`。PC3 將自己的 subnet mask 套用到 destination IP 後，判斷 PC10 不在本地 subnet。

```text
PC3 所在 subnet  = 172.16.1.64/26
PC10 所在 subnet = 172.16.1.0/26
                    不相同
                       ↓
Next hop = VLAN 20 default gateway 172.16.1.65
```

> [!important]
> Destination IP 仍是 PC10；PC3 只把 Ethernet frame 的 destination MAC 設為 default gateway 的 MAC。

若 PC3 尚未快取 gateway MAC，會先對 `172.16.1.65` 執行 ARP。R1 的 `G0/0.20` 回覆，而其 MAC 與 physical `G0/0` 及其他 subinterfaces 相同。

## Step 2：PC3 建立第一個 Ethernet Frame

PC3 建立的初始 frame 可抽象表示為：

```text
Ethernet frame
├─ Src MAC = PC3-MAC
├─ Dst MAC = R1-G0/0-MAC
└─ IP packet
   ├─ Src IP = PC3-IP
   └─ Dst IP = PC10-IP
```

PC3 連接 switch access port，因此送出的 frame 沒有 802.1Q tag。Switch 根據 ingress access port，將它分類到 VLAN 20。

## Step 3：SW1 將 VLAN 20 Frame 送上 ROAS Trunk

PC3 直接連到 SW1。SW1 查詢 VLAN 20 的 MAC address table，得知 gateway MAC 位於連向 R1 的 `G0/1` trunk。

Frame 從 trunk 送出時，SW1 加入 VLAN 20 tag：

```text
PC3
 │ untagged，ingress access VLAN 20
 ▼
SW1
 │ tagged，802.1Q VID = 20
 ▼
R1 G0/0 trunk
```

此時 MAC 與 IP 欄位尚未因 switch forwarding 而改變；SW1 只加入供 trunk 接收端識別 VLAN 的 tag。

## Step 4：R1 將 Frame 分派給 G0/0.20

R1 的 physical `G0/0` 收到 tagged VLAN 20 frame，依 VLAN ID 將它交給設定了 `encapsulation dot1q 20` 的 `G0/0.20`。

```text
802.1Q VLAN ID 20
        ↓
R1 G0/0.20
        ↓
Destination MAC = R1-G0/0-MAC
        ↓
移除原 Ethernet header/trailer
```

Router 接著處理其中的 IP packet，而不是延用原本的 Ethernet frame。

## Step 5：R1 根據 Destination IP Routing

R1 查詢 routing table。PC10-IP 落在 directly connected 的 `172.16.1.0/26`，其 Layer 3 exit interface 是 `G0/0.10`。

```text
Destination IP = PC10-IP
        ↓ longest-prefix match
172.16.1.0/26 is directly connected
        ↓
Exit subinterface = G0/0.10
```

Routing 過程會讓 TTL 減 1，並重新計算必要的 Layer 3 header 欄位；端到端的 source/destination IP 基本保持為 PC3-IP 與 PC10-IP。

## Step 6：R1 建立 VLAN 10 的新 Frame

R1 若尚未知道 PC10-MAC，會先在 VLAN 10 執行 ARP。取得 PC10-MAC 後，R1 建立新的 Ethernet frame：

```text
New Ethernet frame
├─ 802.1Q VID = 10
├─ Src MAC = R1-G0/0-MAC
├─ Dst MAC = PC10-MAC
└─ IP packet
   ├─ Src IP = PC3-IP
   └─ Dst IP = PC10-IP
```

`G0/0.10` 設定了 `encapsulation dot1q 10`，因此它送出的 traffic 經 physical `G0/0` 時會標記為 VLAN 10。

> [!important]
> Router 丟棄 PC3 → R1 的舊 Layer 2 frame，再建立 R1 → PC10 的新 Layer 2 frame。這就是跨 subnet 時 MAC 位址改變、IP 位址維持端到端意義的原因。

## Step 7：SW1 與 SW2 Forward VLAN 10 Frame

SW1 `G0/1` 從 R1 收到 tagged VLAN 10 frame，將其歸入 VLAN 10。因 PC10 連在 SW2，SW1 從與 SW2 相連的 `G0/0` trunk 送出 frame，VLAN 10 tag 仍然存在。

SW2 從 trunk 收到 frame 後，查詢 VLAN 10 的 MAC address table，將 frame 送至 PC10 所連接的 access port。送出 access port 前移除 tag，PC10 收到一般 untagged Ethernet frame。

## Complete Packet Flow

```text
PC3 (VLAN 20)
 │ untagged; Dst MAC = R1
 ▼
SW1 access port
 │ classify as VLAN 20
 ▼
SW1 G0/1 trunk
 │ tagged VLAN 20
 ▼
R1 G0/0 → G0/0.20
 │ remove old L2 frame
 │ route by PC10 destination IP
 ▼
R1 G0/0.10 → G0/0
 │ new frame; tagged VLAN 10
 ▼
SW1 G0/1
 │ tagged VLAN 10
 ▼
SW1 G0/0 ===== trunk ===== SW2 G0/0
 │ tagged VLAN 10
 ▼
SW2 access port
 │ remove tag
 ▼
PC10 (VLAN 10)
```

## Header and Tag Changes

| Path segment | Src MAC | Dst MAC | Src IP | Dst IP | 802.1Q tag |
|---|---|---|---|---|---|
| PC3 → SW1 access port | PC3 | R1 G0/0 | PC3 | PC10 | None |
| SW1 → R1 trunk | PC3 | R1 G0/0 | PC3 | PC10 | VLAN 20 |
| R1 → SW1 trunk | R1 G0/0 | PC10 | PC3 | PC10 | VLAN 10 |
| SW1 → SW2 trunk | R1 G0/0 | PC10 | PC3 | PC10 | VLAN 10 |
| SW2 access port → PC10 | R1 G0/0 | PC10 | PC3 | PC10 | None |

## Configuration That Makes the Flow Possible

Switch 端必須是允許 VLAN 10、20、30 的 trunk；router 端則以 subinterfaces 將 tag 對應到 gateway IP：

```text
R1(config)# interface g0/0
R1(config-if)# no shutdown
R1(config-if)# interface g0/0.10
R1(config-subif)# encapsulation dot1q 10
R1(config-subif)# ip address 172.16.1.1 255.255.255.192
R1(config-subif)# interface g0/0.20
R1(config-subif)# encapsulation dot1q 20
R1(config-subif)# ip address 172.16.1.65 255.255.255.192
R1(config-subif)# interface g0/0.30
R1(config-subif)# encapsulation dot1q 30
R1(config-subif)# ip address 172.16.1.129 255.255.255.192
```

Subinterface 編號（例如 `.20`）只是 identifier；真正將 subinterface 綁定 VLAN 20 的是 `encapsulation dot1q 20`。編號與 VLAN ID 保持一致是便於維護的慣例，不是協定要求。

## Native VLAN Effect

如果 ROAS trunk 使用 native VLAN，該 VLAN 的 frame 預設不帶 tag。Router 端可以：

1. 在對應 subinterface 使用 `encapsulation dot1q <vlan-id> native`；或
2. 將 native VLAN 的 IP address 直接設定在 physical interface。

Router 與 switch 的 native VLAN 必須一致，否則 untagged traffic 會被兩端歸入不同 VLAN。

## Common Confusions

- ROAS trunk 上的 ingress VLAN 20 tag 不會在 routing 後繼續變成 VLAN 10；R1 會拆掉舊 frame 並建立另一個標記 VLAN 10 的新 frame。
- Subinterfaces 共用 physical interface 的 MAC address，但各自有不同 IP address 與 VLAN encapsulation。
- Trunk 負責攜帶多個 VLAN；真正讓 VLAN 20 到 VLAN 10 的是 router 的 Layer 3 routing。
- PC3 不會把 frame 直接送到 PC10-MAC，因為 PC10 位於 remote subnet；第一個 destination MAC 是 default gateway。

## Questions

- 為什麼 PC3 → R1 與 R1 → PC10 的 IP endpoints 不變，但 MAC endpoints 不同？
- R1 如何在所有 subinterfaces 共用 MAC address 時，判斷 ingress frame 屬於哪個 subinterface？
- 若 SW1 到 R1 的 trunk 不允許 VLAN 20，封包流程會在哪一步停止？
- 若 `G0/0.20` 誤設為 `encapsulation dot1q 30`，VLAN 20 traffic 為什麼無法到達正確 gateway？
